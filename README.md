# Drollery

A self-hosted library for memes and funny video / audio clips. Gather them from anywhere, let
small local models (or any API you choose) name, tag and transcribe them, and find them again
instantly with full-text search.

> *drollery* (n.): the comic doodles medieval scribes drew in manuscript margins — arguably the first memes.

**Status:** early (v0.1). Web app + HTTP API work. Browser extension and Android app are planned and will use the same API.

## Features

- **Fast full-text search** (SQLite FTS5, prefix matching, ranked): titles, descriptions, tags, transcripts, source URL.
- **Images, GIFs, clips and sounds** (plus albums). A GIF is told apart from other pictures: its own filter and tile mark, and `kind` is `gif` in the API (`image`, `gif`, `video`, `audio`, `album`). Thumbnails and metadata via ffmpeg. Duplicates (same content) are detected and not stored twice.
- **Albums and audiobooks.** A whole album (or audiobook) sits behind one library card with its cover as the card image. Upload the audio files or one ZIP; the tracks are ordered by their track numbers, and the cover comes from your upload, from the ZIP, or from the picture inside the first track. The album page plays the tracks one after another and can download everything as a ZIP.
- **Online album lookup.** For an album or audiobook, press "Look up details online" (or tick the box on the add form) to search MusicBrainz and the Cover Art Archive, both public and free. You pick the matching release, see every proposed change (title, artist, release details, cover, track names matched to your tracks even when a track is missing) and take over only what you tick. The album page then shows a Details panel: release date and original release, record label, catalog number, country, format, type, genres, language and barcode (all searchable, genres link to the library search). Nothing is sent unless you ask, only the album title and artist leave your server, and the client name is just `Drollery/<version>`. Switch it off with `metadata_lookup = false` in `config.toml`; `metadata_user_agent` adds a contact URL if you want to give one.
- **Add by upload or by link.** Direct media URLs, anything `yt-dlp` supports, and gallery pages via `gallery-dl` — downloaded by a background job.
- **Optional, pluggable AI** — nothing is required, nothing is bundled, everything is configurable (see below). Jobs are queued, retried, and run one at a time so a Raspberry Pi stays responsive.
- **Your edits win.** A title you set by hand is never overwritten by AI.
- **Playful, themeable UI.** Light, dark or follow-the-system, a weathered stone-wall texture (generated by `scripts/gen_stone.py`), and 10 vivid highlight colors from the palette button in the header; the choice is remembered per browser.
- **Medieval doodles.** Line-art knights, snails, dragons, wizards, castles, chests and burglars decorate the empty states, login and 404 pages, and a row of tiny scenery stands on the header edge.
- **Custom card images.** For any picture or video, crop a square for its card on the library page: drag and zoom the crop on a picture, or scrub a video to an exact moment (with ±0.1 s and ±1 s steps), take that frame and crop it. The original file is never changed, and the automatic card can be restored.
- **Movies, parodies and synchros.** Add a movie (one video file, up to `max_movie_mb`, 16 GB by default) and mark it as a film, a parody or a synchro (a dub with new voices); a parody or synchro also remembers the original film. "Look up on IMDb" searches IMDb's own search service (no account needed: title, year, main cast, poster) and, with a free [OMDb](https://www.omdbapi.com/apikey.aspx) key entered under Settings → Online lookup, also takes over the plot, genres, directors, the full cast, the rating and the runtime. You see every change before it is applied; the poster can become the card image. IMDb's title pages themselves sit behind a bot check and are not read. Only the title you typed (and the picked IMDb id) is sent, the client name is just `Drollery/<version>`, and the key is stored on your server and never shown again. Movies are never transcribed or named automatically (they run for hours); the details are searchable.
- **Creators and people involved.** A global list of people (name, picture, age, gender, a social media link), each stored once. On any item, type a name to look the person up and add them, or use "New person" to fill in their details in a popup. A person's page lists everything they appear on, and items are found by the names of their people. Shared public pages never show them.
- **One way in, with progress.** The top of the library is a single upload zone: drop files anywhere on the page, choose them, or paste a link (a pasted link or picture is picked up as well). A panel then shows what was picked and suggests what it should become: separate items, an album or audiobook (several audio files or a ZIP, a picture among them becomes the cover) or a movie, parody or synchro (one video file). You confirm the type, fill in its details (with the option to look it up on MusicBrainz or IMDb afterwards) and the upload runs with a progress bar showing the percentage, the amount sent, the speed, the time left and a Cancel button; when the last byte is sent it says that the server is storing and checking the file. The album and movie forms (`/albums/new`, `/movies/new`) still exist, and without scripts the page falls back to a plain form. If you run Drollery behind a reverse proxy, allow long requests there (a large file is checked after it has arrived) and a body size that fits `max_movie_mb`.
- **Share a picture, clip or album** with a public link (for an album: the whole album with a player and a ZIP, or a single track), permanent or temporary (1 hour to 1 year), with an optional label, a view counter and instant revoke. The page needs no login, shows only the title and description (never your tags), and has link-preview tags for chat apps.
- **Your tags and the AI's tags stay apart.** Editing yours never touches the AI's, a re-run replaces only the AI's, and a tag you remove is not suggested again.
- **Accounts and security.** First-run admin setup, scrypt-hashed password, optional two-factor authentication (TOTP with backup codes), login throttling, and per-device API keys for the browser extension and the Android app.
- **Multilingual.** English, German, Spanish, French, Italian, Dutch, Polish, Swedish and Greek; each person picks a language under Settings › Profile, or lets it follow the browser. Adding a language is one file (see Translating).
- **One container**, one data volume, no external services.

## Quick start

```bash
git clone https://forgejo.scriptknight.de/scriptknight/drollery.git && cd drollery
docker compose up -d --build
docker compose logs drollery   # shows the one-time setup code
```

Open <http://localhost:8080>, enter the setup code from the log and create the admin account. All data (database, media, thumbnails, `config.toml`) lives in the
`drollery-data` volume; back it up like any Docker volume.

## Configuration

AI models are managed in the web UI (**Settings > AI models**): define a model, assign it to a job, test the connection. The file below is the fallback for anything you leave on "From config.toml".

On first start `config.default.toml` is copied to `/data/config.toml` inside the volume. Edit it and restart:

```bash
docker compose exec drollery vi /data/config.toml   # or: docker cp
docker compose restart
```

### Local speech-to-text (Whisper) as a second container

The compose file includes an optional Whisper server ([Speaches](https://github.com/speaches-ai/speaches), faster-whisper with int8 quantization on CPU), running the **small** model. It is not published to the host; Drollery reaches it at `http://whisper:8000/v1`.

```bash
echo 'COMPOSE_PROFILES=whisper' >> .env    # opt in
docker compose up -d                       # starts whisper and downloads the model (~460 MB) once
```

Then open **Settings > AI models**, add a model with the **Whisper server** preset and assign it to **Transcription**. The model name must match `WHISPER_MODEL` (default `Systran/faster-whisper-small`; use `-tiny`, `-base`, `-medium` or `-large-v3` for other sizes). The container is capped at `WHISPER_CPUS` (default 4) and `WHISPER_MEM_LIMIT` (default 3g), and unloads the model after 10 idle minutes.

**Speed depends on the CPU.** Whisper's fast int8 code needs AVX2. On a virtual machine whose CPU type hides it (e.g. a generic `QEMU Virtual CPU`), transcription runs about as fast as real time with `small`, several times slower than it should. Check with `grep -c avx2 /proc/cpuinfo`; if it prints 0, set the VM's CPU type to `host` in the hypervisor.

### AI providers

Two independent capabilities, each off by default (`type = "none"`):

| Section | Does | Input |
|---|---|---|
| `[transcribe]` | speech-to-text for audio and video | extracted mono 16 kHz MP3 |
| `[describe]` | title, description and tags | 640 px preview image and/or the transcript |

Provider types:

| `type` | Use for |
|---|---|
| `openai` | **Any OpenAI-compatible HTTP API.** Ollama (`http://host.docker.internal:11434/v1`), llama.cpp server, LocalAI, faster-whisper-server, OpenAI, OpenRouter… Run the model on the Pi, on another box in your network, or in the cloud — it is just a URL. |
| `command` | A local program that prints the result to stdout, e.g. `whisper-cli -m /models/ggml-tiny.bin -f {input} -nt`. `{input}` is replaced by the file path. |

API keys are never stored in the config: set `api_key_env = "DESCRIBE_API_KEY"` and put the key in `.env`.

Example — name and tag with a small vision model on a LAN machine, transcribe with a whisper server:

```toml
[describe]
type = "openai"
base_url = "http://192.168.1.50:11434/v1"
model = "moondream"

[transcribe]
type = "openai"
base_url = "http://192.168.1.50:8000/v1"
model = "Systran/faster-whisper-tiny"
```

Adding a new provider type is a function plus one line in the registry dict at the bottom of the matching section of `src/drollery/providers.py`.

## HTTP API

All endpoints take `Authorization: Bearer <api key>`. Create keys per device in **Settings > API keys** (a key is shown once and stored only as a hash). `GET /api/v1/me` checks a key.

| Method | Path | |
|---|---|---|
| `GET` | `/api/v1/items?q=&kind=&tag=&tag_source=&limit=&offset=` | search / list. Items carry `tags` (yours) and `ai_tags`; `tag_source` is `user` or `ai` |
| `GET` | `/api/v1/items/{id}` | one item |
| `POST` | `/api/v1/items` | upload (`multipart`, field `file`) |
| `POST` | `/api/v1/albums` | create an album (`multipart`: `files` = audio files and/or ZIPs, optional `cover`, `title`, `artist`, `subtype` = `album`\|`audiobook`, `description`, `tags`) |
| `POST` | `/api/v1/ingest` | `{"url": "https://…"}` — queue a download |
| `PATCH` | `/api/v1/items/{id}` | `{"title","description","tags"}` |
| `DELETE` | `/api/v1/items/{id}` | |
| `GET` `POST` | `/api/v1/items/{id}/shares` | list / create share links. Body: `{"expires_in": seconds or null, "label": "", "track_id": album track or omit for the whole album}` |
| `DELETE` | `/api/v1/shares/{id}` | remove a share link |
| `GET` | `/api/v1/jobs` | queue state |
| `POST` | `/api/v1/jobs/{id}/retry` | run one failed job again (`409` if it isn't failed) |
| `GET` | `/media/{id}`, `/thumb/{id}` | files. An album has `url: null`; use `/albums/{id}/track/{track}`, `/albums/{id}/cover` and `/albums/{id}/download` |

## Security notes

- **Use HTTPS** if the site leaves your LAN (a reverse proxy is fine) and set `DROLLERY_COOKIE_SECURE=1`. Passwords and keys otherwise travel unencrypted.
- **First-run setup needs the setup code** from the container log, so nobody who merely finds the port can claim the admin account. It is deleted once the admin exists.
- Passwords are hashed with scrypt. Sign-in attempts are rate-limited, 2FA codes can't be replayed, and browser writes from other sites are rejected.
- AI model API keys you enter in the UI are stored in the database inside the data volume and are never shown again or returned by any endpoint. Protect the volume (backups included) like any secret.
- **Share links** are capability URLs: anyone who has one can open that single item until it expires or you revoke it (Settings › Shares lists them all). They are served `noindex`, without referrers, and with a sandboxing policy so even a hostile file can't run script. SVG uploads are refused for that reason. To share beyond your network, expose the server and set its address in Settings › Shares (or `DROLLERY_PUBLIC_URL`).
- `/api/v1/ingest` makes the server fetch arbitrary URLs. That is the feature, but it means anyone holding an API key can make the container request addresses on your network. Revoke keys you no longer use.

### Translating

The English text in the code is the key; a language is a single file, `src/drollery/locales/<code>.py`, with `NAME` and a `MESSAGES` dict (copy `de.py`). List the code in `LOCALES` in `src/drollery/i18n.py` and it appears in Settings › Profile.

- `t("Text")` in Python and `_("Text")` in templates mark a string; `{name}` placeholders keep their names in every language, and plurals are `(one, other)` pairs (`tn` / `_n`).
- `python scripts/i18n_scan.py` lists what a catalog still lacks. The tests fail when a string is missing or a placeholder differs.
- Titles, tags and the Impressum text are your own content and are never translated. The JSON API always answers in English.
